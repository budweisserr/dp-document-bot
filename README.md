# dpq — монітор е-черги ДП «Документ»

Rust-бот: стежить за вільними слотами електронної черги `*.pasport.org.ua`
і надсилає Telegram-сповіщення, щойно вони з'являються.

## Як це працює (перевірено на живому сайті, жовтень 2026)

1. **Cloudflare.** Звичайний HTTP-клієнт отримує `403 Just a moment`, а клієнт із
   Chrome-відбитком TLS/JA3+HTTP/2 — `200`. Тому використовується `wreq` з
   профілем Chrome; браузер не потрібен.
2. **Сторінка черги** — SSR. У ній є Alpine-конфіг
   (`qlogickFormHaku({...})` або старіший `qlogickForm({...})`) з числовим
   `center` і `csrf`-токеном поточної сесії.
3. **JSON API сайту** (POST на ту саму адресу сторінки, `x-www-form-urlencoded`):
   - `form=days` → `{"days":[{"datePart":"…","allowedJobCount":N,"isAllowed":true}]}`;
   - порожній масив = вільних місць немає (це і є основна перевірка);
   - поле з іменем, рівним `csrf`-токену, зі значенням `1`.
   Сайт відкидає «не-браузерні» POST-и відповіддю `Помилка доступу!`, тому клієнт
   надсилає `Origin`, `Referer` і `Sec-Fetch-Dest/Mode/Site` як справжній XHR.
4. **Мінімум запитів.** Токен сесії перевикористовується, доки сервер його
   приймає; сторінка (180 КБ) читається лише коли токена немає або він перестав
   працювати. У стабільному режимі це **один маленький POST на перевірку**.
5. **При 429/челенджі** — пауза 10 хв, далі 20/40/60 хв (стеля з конфіга), плюс
   мінімальний інтервал `REQUEST_GAP_MS` між будь-якими запитами.

**Межа автоматизації.** Запис завершується підтвердженням номера телефону
(SMS/Viber-код); для частини центрів додається hCaptcha. Ці кроки бот свідомо не
обходить: він дає точні дати й посилання, а капчу та код підтверджує людина.

## Швидкий старт

```bash
cp .env.example .env       # вписати BOT_TOKEN
cargo build --release
./target/release/dpq
```

Без `BOT_TOKEN` бот працює в режимі «тільки монітор» і пише знайдені слоти в лог.

## Деплой на Amazon Linux / VPS

Один скрипт ставить залежності, збирає бінарник, створює systemd-сервіс
`dpq` і запускає його:

```bash
# на інстансі, з кореня проєкту:
sudo ./deploy.sh
sudo nano /opt/dpq/.env          # BOT_TOKEN
sudo systemctl restart dpq
journalctl -u dpq -f
```

`deploy.sh` розрахований на Amazon Linux 2023 / RHEL-родину (dnf) і x86_64.
Споживання бота: **~6–10 MB RSS, ~0 % CPU**, один маленький POST раз на
`CHECK_INTERVAL`; порти не потрібні, тільки вихідний HTTPS.

**Важливо про IP.** Сайт рахує ліміти й Cloudflare-довіру за IP. IP дата-центру
(AWS/GCP) для Cloudflare «холодніший», ніж домашній: перевірте бота на інстансі
перед тим, як на нього покладатися. Якщо починає часто віддавати челенджі/429 —
або тримайте бота вдома, або вкажіть резидентський `PROXY=` в `.env`. Також
закріпіть IP (Elastic IP), бо після stop/start він змінюється і сесія втрачається.

### Статичний бінарник (опційно)

Якщо не хочеться збирати на інстансі — можна зібрати локально статичний
musl-бінарник, який працює на будь-якому x86_64 Linux (Ubuntu, Amazon Linux,
Alpine):

```bash
rustup target add x86_64-unknown-linux-musl
curl -LO https://musl.cc/x86_64-linux-musl-cross.tgz && tar -xzf x86_64-linux-musl-cross.tgz -C /opt
export PATH=/opt/x86_64-linux-musl-cross/bin:$PATH
export CC_x86_64_unknown_linux_musl=x86_64-linux-musl-gcc CXX_x86_64_unknown_linux_musl=x86_64-linux-musl-g++
export CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_LINKER=x86_64-linux-musl-gcc
cargo build --release --target x86_64-unknown-linux-musl
```

## Проксі

- `PROXY=` — один постійний проксі (`http://user:pass@host:port` або
  `socks5://host:port`). Якщо він заданий, список ігнорується.
- `PROXY_LIST=` — файл або URL зі списком, по одному `scheme://host:port` на
  рядок. Наприклад:
  `PROXY_LIST=https://raw.githubusercontent.com/monosans/proxy-list/main/proxies/all.txt`
- На старті (і раз на `PROXY_REFRESH_HOURS`, або коли пул спорожнів) бот бере
  випадкові 200 записів і **паралельно перевіряє** їх через `https://api.ipify.org`,
  лишаючи тільки робочі. У замірі з monosans — 55/200.
- На транспортній помилці, `403` (Cloudflare challenge) або `429` поточний
  проксі відкидається, береться наступний. `403` дає коротку паузу
  `CHALLENGE_SECS=30`, `429` — повний `BLOCKED_SECS` (600 с, далі х2). Кількість
  запитів при цьому не зростає.
- Заміряно на цьому сайті: безкоштовні проксі — переважно дата-центрові IP, і
  Cloudflare на `pasport.org.ua` віддає їм `403`/`429`. Для цієї задачі
  безкоштовний список — не рішення; якщо потрібен інший вихідний IP, краще
  платний резидентський у `PROXY=`.
- Хочете швидше перебирати пул — поставте менший `BLOCKED_SECS` (мінімум 120).

## Команди бота

- `/start` — меню та статус підписки
- `/check` — перевірити обране місто зараз
- `/subscribe` / `/unsubscribe` — увімкнути/вимкнути сповіщення
- `/cities` — змінити місто
- `/status` — стан і останній результат

## Міста

Ключі міст лежать у `src/config.rs`. Для міст, де числовий `ServiceCenterId`
ще невідомий, він визначається автоматично зі сторінки під час першого
відкриття форми й зберігається в `data/centers.json`.
`SERVICE_ID=4` — «Закордонний паспорт та (або) ID-картка» (перевірено на
Варшаві й Кракові; id видно в `<option>` на сторінці).

## Чому так повільно (і чому це правильно)

Сайт має жорсткий ліміт запитів: серія з ~5 запитів за кілька хвилин дає
`429 Too many requests` і блокує IP на 10–25 хвилин (перевірено). Тому дефолтний
інтервал — 300 с, між запитами — 5 с, а будь-який `429` вмикає довгу паузу.
Слоти з'являються у довільний час, тож виграш від агресивнішого полінгу
нульовий, а ризик бана — реальний.
